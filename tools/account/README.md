# Личный кабинет tikteam.live: сборка и проверки

Клиентская часть кабинета по контракту `/api/web/v1` (сервер — зона Codex).
Обычный HTML, CSS и ES-модули, без фреймворков и зависимостей.

## Страницы и файлы

| Путь | Что это |
|---|---|
| `account/`, `en/account/` | Вход, регистрация, «забыли пароль» и кабинет |
| `account/recovery/`, `en/account/recovery/` | Подтверждение почты и новый пароль по ссылке из письма |
| `assets/css/account.css` | Стили кабинета поверх `site.css` |
| `assets/js/account/` | Код страниц; `config.js` создаёт сборка |
| `tools/account/mock/` | Демо-сервер и демо-панель — только для демо-сборки |
| `tools/account/test/` | Тесты (`node --test`) |

## Режимы сборки

Режим выбирается только при сборке, не адресом страницы, хранилищем или вводом.

```bash
node tools/account/build.mjs --mode disabled
node tools/account/build.mjs --mode mock --out .preview/mock
node tools/account/build.mjs --mode real --api-origin https://api-test.tikteam.live --out .preview/web-test
```

- **disabled** — состояние в репозитории. Страницы говорят «кабинет скоро откроется»
  и не делают запросов (`connect-src 'none'`).
- **mock** — копия сайта с демо-сервером в памяти и демо-панелью. Сеть не используется,
  переходов на оплату нет. Только для локальной проверки, не публикуется.
- **real** — копия сайта, которая обращается ровно к одному API-адресу. В CSP разрешён
  только он. Демо-файлов в ней нет. При недоступном API показывается ошибка, без
  переключения на заглушку или вход программы.

Вывод — только в `.preview/` (игнорируется git) или вне папки сайта.

## Тесты

```bash
node --test tools/account/test/
```

Проверяются: защитный токен и cookie (`credentials: include`, `no-store`), новый токен
после входа, отказ токена без автоматического повтора, ошибки не-JSON прокси, Retry-After,
проверка ссылок оплаты и кабинета Paddle, формат ссылки восстановления, контракт на
демо-сервере (одинаковые ответы, неверный текущий пароль, общий отзыв сеансов, чужой
компьютер, одноразовые и истекающие коды, повторный клик оплаты, права только после
серверной проверки), запрет Web Storage и вставки HTML в публикуемых файлах, CSP страниц
и состав каждой сборки.

## Что нельзя сделать на GitHub Pages

GitHub Pages не отправляет свои HTTP-заголовки. Поэтому:
- `frame-ancestors` и `X-Frame-Options` недоступны. Страницы кабинета скрыты, пока
  `guard.js` не убедится, что их не встроили в чужой сайт. Это слабее заголовка.
- CSP задана через `<meta>`; `Referrer-Policy` — тоже `<meta>`.
Перед открытием кабинета нужен хостинг с настоящими заголовками или проксирование
страниц кабинета через сервер с ними.
