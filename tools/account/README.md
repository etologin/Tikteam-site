# Личный кабинет tikteam.live: сборка и проверки

Клиентская часть кабинета по контракту `/api/web/v1` (сервер — зона Codex).
Обычный HTML, CSS и ES-модули, без фреймворков и зависимостей.

## Страницы и файлы

| Путь | Что это |
|---|---|
| `account/`, `en/account/` | Вход, регистрация, «забыли пароль» и кабинет |
| `account/recovery/`, `en/account/recovery/` | Подтверждение почты и новый пароль по ссылке из письма |
| `assets/css/account.css` | Стили кабинета поверх `site.css` |
| `assets/js/account/` | Код страниц; `config.js` создаёт сборка |
| `tools/account/mock/` | Демо-сервер и демо-панель — только для демо-сборки |
| `tools/account/test/` | Тесты (`node --test`) |
| `tools/account/browser-check.mjs` | Необязательная проверка сценариев в headless Edge/Chrome |

## Режимы сборки

Режим выбирается только при сборке, не адресом страницы, хранилищем или вводом.

```bash
node tools/account/build.mjs --mode disabled
node tools/account/build.mjs --mode mock --out .preview/mock
node tools/account/build.mjs --mode real --api-origin https://api.tikteam.live --out .preview/closed
```

- **disabled** — состояние в репозитории. Страницы говорят «кабинет скоро откроется»
  и не делают запросов (`connect-src 'none'`).
- **mock** — копия сайта с демо-сервером в памяти и демо-панелью. Сеть не используется,
  переходов на оплату нет. Только для локальной проверки, не публикуется.
- **real** — копия сайта, которая обращается ровно к одному API-адресу. В CSP разрешён
  только он. Демо-файлов в ней нет. При недоступном API показывается ошибка, без
  переключения на заглушку или вход программы.

Вывод — только в `.preview/` (игнорируется git) или вне папки сайта.

## Подтверждение почты и Google

- **Сначала профиль.** Кабинет читает `GET /account` отдельно. Пока `emailConfirmed`
  не `true`, на странице только email и его состояние, повторное письмо, «Обновить статус»,
  ссылка для пароля и выход; компьютеры и оплата даже не запрашиваются. Ответ 403
  `email_unconfirmed` на любое действие возвращает к этому экрану без выхода из аккаунта
  и без сообщения «сервер недоступен». Решение принимает `assets/js/account/dashboard.js`.
- **`hasPassword: false`** (аккаунт создан через Google): формы с текущим паролем скрыты,
  первый пароль задаётся одноразовой ссылкой восстановления. Нет поля — значит пароль есть.
- **Google** показывается, только если `GET /auth/google/config` ответил `enabled: true`.
  Вход: `POST /auth/google/start` с `{}`; привязка: тот же запрос с `{currentPassword}`
  и только для подтверждённой почты. Ответ принимается, лишь если ссылка ровно
  `<API origin>/auth/google/#` + 64 hex и `pollToken` пуст; переход — после нажатия, в той
  же вкладке. Ссылка, билет и пароль нигде не сохраняются. После Google сервер возвращает
  браузер на `/account/`, и страница заново спрашивает сеанс и профиль: сам возврат
  ничего не доказывает. В демо-сборке переход отключён; завершение входа — в демо-панели.

## Тесты

```bash
node --test tools/account/test/
node tools/account/browser-check.mjs
```

Проверяются: защитный токен и cookie (`credentials: include`, `no-store`), новый токен
после входа, отказ токена без автоматического повтора, ошибки не-JSON прокси, Retry-After,
проверка ссылок оплаты, кабинета Paddle и входа Google, формат ссылки восстановления,
план кабинета (подтверждение, `hasPassword`, Google), контракт на демо-сервере
(одинаковые ответы, неверный текущий пароль, общий отзыв сеансов, чужой компьютер,
одноразовые и истекающие коды, повторный клик оплаты, права только после серверной
проверки, 403 `email_unconfirmed` без потери сеанса, Google: выключен, старт без poll-токена,
одноразовость и срок, совпадение email без привязки, привязка с текущим паролем, аккаунт
без пароля), запрет Web Storage, вставки HTML и Google SDK в публикуемых файлах, CSP
страниц и состав каждой сборки.

`browser-check.mjs` — необязательная проверка в настоящем движке: собирает демо-версию
в `.preview/browser-check`, отдаёт её на 127.0.0.1 и проводит headless Edge или Chrome
(`TIKTEAM_BROWSER=<путь>`) по сценариям: вход и привязка Google, аккаунт без пароля,
неподтверждённая почта, выключенный Google. Код возврата 2 — браузер не найден.

## Что нельзя сделать на GitHub Pages

GitHub Pages не отправляет свои HTTP-заголовки. Поэтому:
- `frame-ancestors` и `X-Frame-Options` недоступны. Страницы кабинета скрыты, пока
  `guard.js` не убедится, что их не встроили в чужой сайт. Это слабее заголовка.
- CSP задана через `<meta>`; `Referrer-Policy` — тоже `<meta>`.
Перед открытием кабинета нужен хостинг с настоящими заголовками или проксирование
страниц кабинета через сервер с ними.
